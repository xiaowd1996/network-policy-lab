# 审计与监控解释

仓库保留的是审计、TCP 采集、健康探测及包装入口监控的代码，不包含采集数据。
运行前应人工审核权限、日志字段、保留期、数据库文件权限与 logrotate；不会自动安装。

应结合三层证据：

- 客户端匹配的规则、进程、目标与代理链。
- 香港入口/出口的连接、握手、错误、重传及域名等元数据。
- 网卡 RX/TX 与运营商同时间窗口统计。

不做 TLS 解密，不记录账号、Cookie、Authorization 或文件内容。
即使只采集域名/IP，也可能暴露使用习惯，数据库与日志应留在私有环境并适度保留。
诊断用户应具有独立身份；不能为了观察某用户而公开整个订阅或混淆各用户的统计。

## 流量口径

代理有效负载、应用展示、Linux 网卡收发和厂商计费可能不同。
转发同一份内容通常既有进站又有出站，厂商按双向合计时可能接近有效数据的两倍，另有协议开销和重传。
不能不对齐起止时间、服务覆盖范围及 GB/GiB 就直接相减。

服务端 `direct` 是香港主机直出，不是客户端本机直出。
客户端的 DIRECT 也可能出现在客户端流量仪表盘里，不能因此认定使用了香港流量。

一次性订阅的历史实现是下载一次激活隔离租约，并在无连接持续一段时间后撤销；
不是每断开一个 TCP 就失效，也不等于正式 A–D 订阅的一次性化。
