# 架构与规则边界

## 客户端

一套 Mihomo 规则与一个 TUN 是基线。不要让两个 TUN 同时接管默认路由。
系统代理和 TUN 是不同接管方式：系统代理只影响遵守代理设置的程序。

日常规则的主要顺序：

1. 局域网、本地地址等必要 DIRECT。
2. 指定 AI 等需要固定住宅出口的规则优先于一般境外选择。
3. 国内应用、P2P、同步工具、Steam/游戏的既有本机 DIRECT 例外。
4. 中国大陆域名与 IP 本机 DIRECT。
5. 其它 TCP 交给出口模式；未匹配 UDP 最终 REJECT。

具体顺序以示例文件中的原始 531 条规则为准，不要按这段摘要重建生产配置。
独立的“严格 XO 路由”与日常策略不同；本次仅导出日常规则，没有将严格 XO 策略混入。

## 服务端

- 传统入口：公网 TCP 443 → sing-box Trojan/TLS → AUTO/HK/XO 对应路由。
- fallback：无有效代理认证的 HTTPS 请求转至 loopback Nginx；仅授权订阅路径有效。
- AUTO：既有指定域名经住宅 SOCKS，其它流量香港直出。
- HK：常规香港出口身份；客户端更高优先级强制住宅规则仍可能选择 XO 身份。
- XO：经住宅 SOCKS 的身份，不能通过其名称推断客户端所有流量都被捕获。
- 独立包装：单独监听与身份映射，不能覆盖现有 443 主入口。
- 可选上游中转：客户端 → 中转 → 香港 → 按规则直出/住宅出口；证书名称须与后端协调。

`198.51.100.10`、`198.51.100.20`、`203.0.113.10`、`192.0.2.10/11` 仅用于说明不同角色，
不是本系统的实际地址，不可用来测试或部署。端口结构保留，但并非推荐为所有环境统一使用。

## Drive/本机额外代理

Drive 经另一款本机纯代理的软件方案属于可选扩展，不是服务器基线。
截至归档整理时，扩展仅做过生成/静态与独立链路检查，未证明已在用户 Fl 中应用或完成真实文件上传下载。
不要用该未验收状态替代服务器代理的正常性证据，也不要把所有 Google API 全局改道。
